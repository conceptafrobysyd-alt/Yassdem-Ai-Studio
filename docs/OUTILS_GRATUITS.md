# Outils gratuits pour simplifier la création

Sélection vérifiée le **26 octobre 2026** par lecture des dépôts GitHub, de leurs README et de leurs licences. Les références ci-dessous sont figées sur les commits consultés. Aucun programme de ces dépôts n'a été exécuté, aucune dépendance ajoutée et aucun poids de modèle téléchargé pendant cette recherche. Les performances annoncées par leurs auteurs ne sont pas des mesures réalisées sur l'ordinateur Windows de l'utilisateur.

Le meilleur premier changement est le parcours **une photo → un résultat choisi → un téléchargement**. FFmpeg et Sharp sont déjà présents dans Yassdem : une vidéo avec mouvement de caméra, un cadrage et une signature de marque peuvent utiliser ces moteurs sans nouveau service. Générer une personne ou faire porter réellement un vêtement par un mannequin demande un modèle supplémentaire ; une simple planche de vêtements ne réalise pas cet essayage.

## Adobe et l'essayage : dépôts examinés, sans activation

Les projets Adobe trouvés ne constituent pas une solution gratuite prête à intégrer pour les contenus commerciaux du studio :

- **[Adobe Research MagicFixup][magic-readme]** répare une image à partir d'une référence et d'une image déjà retouchée. Sa [licence Adobe Research][magic-license] limite l'utilisation à la recherche non commerciale, excluant notamment le développement de produits commerciaux. Ce n'est pas un moteur vidéo à activer pour une boutique.
- **[Adobe Research / Inria VideoDoodles][doodles-readme]** ajoute des animations dessinées sur des vidéos. Sa [licence][doodles-license] impose aussi la recherche non commerciale. Ce n'est pas un remplacement gratuit général d'un service Adobe.

Deux pistes d'essayage illustrent pourquoi il faut examiner toute la chaîne :

- **[IDM-VTON][idm-readme]** prend en charge l'essayage, mais le README place le code **et les checkpoints** sous [CC BY-NC-SA 4.0][idm-license]. Il n'est pas retenu pour un usage commercial par défaut.
- **[FASHN VTON v1.5][fashn-readme]** est une piste intéressante : image de personne + image de vêtement, catégories haut/bas/pièce entière, code sous [Apache 2.0][fashn-license], environ 2 Go de poids annoncés. Cependant, son pipeline télécharge aussi automatiquement **fashn-human-parser**. La [licence de ce composant][parser-license] renvoie à celle de SegFormer, dont la [section 3.3][segformer-license] limite l'usage à la recherche ou l'évaluation non commerciales. **Le pipeline par défaut n'est donc pas retenu comme solution commerciale gratuite.** Remplacer cette dépendance et vérifier les poids demanderait un travail et une validation séparés. Le README ne donne pas de minimum de VRAM fiable à reprendre ici.

Un mannequin de référence autorisé peut être choisi une première fois et réutilisé. L'utilisateur pourra ensuite demander un résultat en un clic, mais cette simplicité de l'interface suppose que le moteur, le modèle et la référence nécessaires aient été configurés. Une illustration de mannequin ou un collage ne doit pas être présenté comme une photo d'essayage calculée.

## Identifier votre carte graphique sur Windows

Ouvrez le **Gestionnaire des tâches** avec `Ctrl` + `Maj` + `Échap`, puis **Performances → GPU**. Le nom affiché en haut à droite permet de choisir un moteur adapté. S'il y a plusieurs GPU, relevez leurs noms et la mémoire dédiée indiquée pour chacun.

Autre méthode : ouvrez une **nouvelle fenêtre PowerShell**, en laissant celle du studio ouverte, puis collez cette commande :

```powershell
Get-CimInstance Win32_VideoController | Select-Object Name
```

Elle affiche les noms des cartes graphiques, sans rien installer ni modifier. Le nom seul ne suffit pas à garantir qu'un modèle tournera correctement ; il permet de commencer le choix. Les fonctions locales de vidéo simple et de cadrage restent disponibles sans GPU dédié.

## Ordre recommandé pour Yassdem

1. **Automatiser l'existant** : après import, proposer la vidéo produit et les formats d'image avec des réglages prêts à l'emploi. Les options détaillées restent accessibles ensuite.
2. **Évaluer le détourage local** avec un modèle dont les conditions commerciales et la provenance sont confirmées. Conserver la photo originale.
3. **Préparer un moteur mannequin facultatif** avec état de disponibilité explicite ; choisir le modèle seulement après vérification de toutes ses dépendances et des caractéristiques du PC.
4. **Évaluer la vidéo générative** Wan ou LTX sur un matériel adapté, sans téléchargement ni dépense automatique.
5. **Garder Shotcut ou Kdenlive comme complément** pour un montage avancé ; surveiller OpenCut lorsque son API sera effectivement stabilisée.

Le code ouvert facilite l'inspection ; il ne prouve ni l'absence de failles, ni la qualité du résultat, ni un droit identique sur les modèles, musiques et photos. Aucun de ces nouveaux moteurs n'a été intégré ou testé en inférence réelle par cette recherche. L'accès HTTP à l'API GitHub et aux fiches Hugging Face était refusé par le proxy ; les README et licences GitHub ont pu être consultés via Git. Les conditions des poids non confirmées restent à vérifier avant une intégration.
